## 今日落地

- 接口从 `IClient`/`IServer` 收敛为**单入口** `on(GameEvent)` / `on(GameCommand)`，内部 `std::visit`。
- 进一步拆成 **4 端口**：
  - 出站：`ClientGateway`（服务器→客户端，`broadcast`/`sendTo`）、`ServerGateway`（客户端→服务器，`send`，**不带身份**）；
  - 入站：`ClientHandler::on(GameEvent)`、`ServerHandler::on(GameCommand, ClientSession)`；
  - `ClientSession { client_id_t id; ClientHandler& handler; }` 由**服务器侧适配器**提供；
  - `LocalLink` 带 `client_id`，投递时补 `ClientSession`。
- 序列化：`Event.hpp` 的 `POKER_*_TYPES` 生成 `get_event_name` 与 `GameEvent`/`GameCommand`/`NetworkEventVariant`；反序列化按 variant alternatives 自动分派；`GeneralSerializer` 用 concept 自动注册。
- 字段序列化改用 **visitor**：`POKER_FIELDS_VISITOR(...)` + `HasVisit` concept + 通用 `adl_serializer`，删掉逐事件 `NLOHMANN_DEFINE_TYPE_NON_INTRUSIVE`。
- 验证：`poker` / `poker_test` / `application` 均可编；76/76 测试全绿；临时程序 round-trip 通过（含 `GameEnded`、`Card` 数组、枚举、命令）。

## 1. 为什么是 4 个端口

原来的 `IServer::on(command, IClient& sender)` 是"本地回环形状"：客户端要自己把 sender 传过去。网络上客户端没有服务器的 `IClient` 对象，sender 应由**服务器侧接入适配器**从连接推断。

于是方向拆开：

| | 出站 | 入站 |
|---|---|---|
| 服务器 | `ClientGateway` | `ServerHandler::on(command, ClientSession)` |
| 客户端 | `ServerGateway::send(command)` | `ClientHandler::on(event)` |

- 客户端发送**不带身份**；
- 服务器入站通过 `ClientSession` 拿到 `id` 与回信通道；
- `client_id_t` 在 join 前就存在，`seat` 在 join 后才分配；两者需要映射。

**待做**：`ClientId → seat` 映射，并在 `handle(SubmitAction)` 里校验"提交者 == 当前行动者"。

## 2. 序列化的演进

旧版问题：引用已删除事件、字段漂移、手写 `if (type == "...")` 长链。

现在的结构：

```
POKER_EVENT_TYPES / POKER_COMMAND_TYPES
        │
        ├─→ get_event_name(...)
        └─→ GameEvent / GameCommand  (std::variant)
                    │
                    └─→ 反序列化按 variant alternatives 自动分派
```

- wire 格式：`{"event": "<类型名>", "data": {...}}`；命令用 `"command"`。
- `type_name<T>()` 走 ADL 找 `get_event_name`。
- `deserialize_variant` 捕获异常 → `nullopt`（网络边界友好）。
- **限制**：wire 名 = C++ 类型名；改 struct 名 = 改协议。

## 3. 字段列表：考虑过的方案

| 方案 | 字段清单 | 字段名 | 评价 |
|---|---|---|---|
| `NLOHMANN_DEFINE_TYPE_NON_INTRUSIVE` | 手写 | ✅ | 简单；漏字段静默 |
| **成员 visitor（已采用）** | 每个 struct 一行 `POKER_FIELDS_VISITOR(...)` | ✅ | 字段定义收进 struct；无宏嵌套 |
| X-macro 即定义 | 宏里写字段 | ✅（需 `(type,name)`） | 真正单点；宏机制重 |
| Boost.PFR | 不用写 | ⚠️ 通常拿不到 | 字段自动；JSON 可能要位置数组 |
| Boost.Describe | 手写 | ✅ | 干净，但仍是列表 |
| C++26 反射 | 不用写 | ✅ | 未来；现在用不了 |
| Schema/IDL + codegen | schema 一处 | ✅ | 最彻底；最重 |

## 4. `POKER_FIELDS_VISITOR` 宏

```cpp
// 用字段名生成 const / 非 const 两个 visit
POKER_FIELDS_VISITOR(btn_seat, big_blind, player_count)
```

展开为：

```cpp
template <class V> void visit(V&& v) {
    v("btn_seat", btn_seat);
    v("big_blind", big_blind);
    v("player_count", player_count);
}
// const 版本同理
```

- 空字段事件：`POKER_FIELDS_VISITOR()`。
- 最多 8 个字段（`TurnStarted` 是 6 个）。
- **为什么不用 `__VA_OPT__` 递归**：同名宏在自身展开期间会被预处理器"涂蓝"，直接递归不会展开；固定元数的 `FOR_EACH` 可靠。
- 成员函数不破坏聚合体，`GameStarted{1, 10, 3}` 仍可用。
- 序列化侧：`HasVisit` concept + 通用 `adl_serializer`，逐事件的 `NLOHMANN_DEFINE...` 全部删除。

## 5. `Event.hpp` 的"围栏"策略

目标：**枚举只出现在 `Event.hpp`；外部模块只依赖 `GameEvent` / `GameCommand`。**

- 外部不要直接用 `POKER_EVENT_TYPES`；
- 值级分派用 `std::visit`；
- 类型级遍历用 `for_each_alternative<Variant>`（可选加入）：

```cpp
template <class Variant, class F, std::size_t... I>
constexpr void for_each_alternative_impl(F&& f, std::index_sequence<I...>) {
    (f(std::type_identity<std::variant_alternative_t<I, Variant>>{}), ...);
}

template <class Variant, class F>
constexpr void for_each_alternative(F&& f) {
    for_each_alternative_impl<Variant>(
        std::forward<F>(f),
        std::make_index_sequence<std::variant_size_v<Variant>>{});
}
```

防御性检查（可放在 `Event.hpp`）：

```cpp
#define POKER_EVENT_CHECK(Type)                                                   \
    static_assert(std::is_copy_constructible_v<Event::Type>);                     \
    static_assert(std::is_default_constructible_v<Event::Type>);                  \
    static_assert(!Event::get_event_name(std::type_identity<Event::Type>{}).empty());
POKER_EVENT_TYPES(POKER_EVENT_CHECK)
#undef POKER_EVENT_CHECK
```

消费方兜底，避免一屏模板报错：

```cpp
template <class...> inline constexpr bool always_false = false;

template <class T>
void handle(const T&) {
    static_assert(always_false<T>, "未处理的 GameEvent 类型：请加 handle 重载");
}
```
