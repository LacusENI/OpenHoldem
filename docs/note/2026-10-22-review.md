# 评审：`IClient` / `IServer` 设计（2026-10-22）

> 状态：**评审记录**（2026-10-22）
> 评审对象：`docs/note/2026-10-22.md` 及其实现在 `include/core/interface/`、`include/core/server/`、`include/core/client/` 的落地。
> 结论：**方向正确、结构清爽；但目前是"单客户端本地回环"的骨架，不是"多客户端联网"的骨架。** 上网络前需补三件事：**发送者身份、生命周期/断线、错误/序号**。

## 1. 总评

相比旧的 `EventBus + ServerIoAdapter` 方案，这版是明确进步：

- 入站命令（`IServer`）与出站事件（`IClient`）分离；
- `core` 定义端口，应用层/本地回环实现（依赖倒置）；
- 强类型逐事件回调 + 成员函数指针分发；
- `ClientHub` 显式承担"广播/单传"；
- `LocalLink` 用异步 FIFO 模拟网络语义，单进程可跑完整回环。

它足以支撑当前 demo（1 个 `ClientController` + 若干 bot、单客户端）。**但多客户端/真实网络下的关键件还缺。**

### 落地状态（2026-10-22 本轮）

- ✅ **已落地**：方向拆为 **4 端口**——`ClientGateway`（服务器出站）/ `ServerGateway`（客户端出站）/ `ClientHandler`（客户端入站）/ `ServerHandler`（服务器入站）；`ServerHandler::on(GameCommand, ClientSession)` 的 sender 由服务器侧适配器补；`LocalLink` 带 `client_id_t`。
- ⏳ **仍待**：`ClientId → seat` 校验、生命周期/断线、错误/序号、网络适配器命名。
- 📝 **X-macro 不再是首选**：改用单入口 `on(...)` + 4 端口；序列化 dispatch 仍需单独处理。

## 2. 优点

1. **方向分离清晰**：`Command::` 与 `Event::` 不混。
2. **依赖倒置到位**：`IClient` / `IServer` 在 core，`LocalLink`、测试 bot、未来的网络适配器都只是实现。
3. **编译期类型安全**：`ClientHub::broadcast(&IClient::onX, e)` 无需 variant/visitor 样板。
4. **路由显式**：公开事件 `broadcast`，私密（底牌）与"轮到你" `sendTo`，写在产生地 `ServerController`。
5. **`LocalLink` 设计聪明**：端点只入队、`pump()` 统一投递，避免回调内同步重入，且与网络"发送即返回、接收稍后"语义一致。
6. **可测/可扩展**：`NullClient` 让 bot、录制器、空实现都很好写。

## 3. 问题（按严重度）

### P0 · 命令缺"发送者身份"

```cpp
virtual void onJoin(IClient& client, const JoinRequest&) = 0;
virtual void onStart(const StartGame&) = 0;       // 谁在开局？
virtual void onSubmit(const SubmitAction&) = 0;   // 谁在下注？
```

`onJoin` 带了 `IClient&`，`onStart/onSubmit` 却没带。服务端只能依赖
`BettingRound::getActingPlayer()` **假设"提交者 == 当前行动者"**（见 `ServerController::onSubmit`）。

本地单客户端成立；真实服务器下会出问题：

- 非当前行动者提交 → 无法拒绝 / 无法归属；
- 多连接、乱序、重连 → 无法判断来源；
- 任何人可 `onStart`（无权限 / 无归属）。

**建议**：`onSubmit(IClient&, SubmitAction)`、`onStart(IClient&, StartGame)`（或命令带 `client_id/seat`/session token），并校验"提交者 == 当前行动者"。

### P0 · 缺生命周期 / 断线 / 错误模型

- `ClientHub` 保存**非拥有** `IClient*`；`sendTo` 在目标座位无客户端时**直接 `assert`**。真实场景"该玩家断线/超时"是常态，会直接崩。
- 没有 `JoinRejected`（满桌 / 游戏已开始 / 重复座位）、没有 `ActionRejected{reason}`。
  - 现在"无效行动"靠**重发 `TurnStarted`** 隐式表达，客户端无法区分"你非法"与"又轮到你"。
- 没有**序号 / `hand_id`**：断线重连、丢包检测、幂等都无法做。
- `ServerController::startNextHand()` 是公开方法但**不在 `IServer` 中**——协议上没有"下一手"命令；demo 打完一手停在 `SETTLEMENT`。多手/赛事需补 `Command::NextHand` 或自动开局策略。

### P1 · 事件列表在多处重复

新增一个事件，至少要改：

- `IClient`（加纯虚）
- `NullClient`（加空实现）
- `LocalLink`（`ServerEndpoint::onX` + `deliver` 的 `if constexpr` 分支）
- `ClientController`（override）
- 序列化（加 case）
- 日志

`LocalLink::deliver` 的 `if constexpr` 链本质是把类型列表**又抄了一遍**。

**建议**：用 **X-macro / 单一事件清单**生成这些代码（`#define POKER_EVENTS(X) X(JoinResponse) X(PlayerJoined) ...`），加事件只改一处。比"换成 `GameEvent` variant + visitor"更贴合现有强类型风格。

### P1 · `IClient` 是"胖接口"，且混了三种语义

13 个纯虚方法混着：公开事实、私密事实、**行动请求**（`TurnStarted`）。玩家少、实现少时没问题；一旦有观战者 / 只关心部分事件的 AI / 日志消费者，就违反接口隔离。

**建议（可后置）**：拆成 `IClient`（广播）+ `IPlayerClient`（私密 / 行动请求）。

### P2 · 命名容易混淆

- 文档中 `LocalServer/LocalClient` 实际是 `ServerController/ClientController`；
- 网络版叫 `RemoteServer/RemoteClient`。

于是：客户端进程里的 `RemoteServer` 是"远端服务器的代理"，服务端进程里的 `ServerController` 才是真服务器；两边都叫 Server，读起来绕。

**建议**：`RemoteServer → ServerProxy`、`RemoteClient → ClientProxy`（或 `ServerStub`），区分"代理"与"实体"。

### P2 · 其他

- `LocalLink::pump()` 超轮数只有 `assert`；Release 下 `assert` 失效会**静默退出**。建议返回 `bool` / 抛异常 / 明确错误返回。
- `TurnStarted` 仍带派生字段（`player_chips/player_bet/round_bet/min_raise/can_raise`），与"传事实不传派生"相悖（文档已注明临时，需还债）。
- `Command::SubmitAction` 仍无 `is_all_in`，与 `event-protocol.md` 提案不一致。
- `ClientHub` 同时管注册（add/remove）与分发（broadcast/sendTo），SRP 略糊；可拆 `SessionRegistry`。

## 4. 对设计文档本身的评价

`2026-10-22.md` 的类图与两条流向**清楚、够用**，但作为"联机基座设计"还缺：

- **所有权 / 生命周期**：`IClient` 由谁拥有？断线谁 `remove`？`RemoteClient` 何时销毁？
- **身份与鉴权**：命令怎么带发送者、谁有权限 `StartGame`。
- **错误 / 拒绝**语义。
- **序号 / 重连**。
- **非目标**：明确"本版只支持本地回环 / 单客户端"。

## 5. 建议的推进顺序

1. **命令带身份**（`onSubmit(IClient&, ...)` / `onStart(IClient&, ...)`），并校验"提交者 == 当前行动者"。
2. **补错误与生命周期**：`JoinRejected`、`ActionRejected{reason}`、断线/超时（不再 `assert`）、`Command::NextHand`。
3. **事件清单单一真源**（X-macro），消掉 `IClient/NullClient/LocalLink/序列化` 的重复。
4. **序号 / `hand_id`**，为断线重连铺路。
5. **命名**：`RemoteServer → ServerProxy`、`RemoteClient → ClientProxy`。
6. （可后置）拆分 `IClient`、`ClientHub` 注册与分发分离。
